# 仕様・実装・設計判断を残す運用

作成日: 2026-10-01（JST）
状態: 採用。Discord Bot v2のドキュメント運用を引き継ぐ。

## 1. 目的

次の実装や修正で、コードの目的・現行挙動・依存関係・過去の判断を確認できる状態を保つ。仕様、実際の実装、未検証の案を混ぜず、それぞれの状態を明記する。

参照元はDiscord Bot v2の `AGENTS.md` 、 `docs/engineering/COMMANDS.md` 、 `docs/architecture/` 、 `docs/implementation/` 、 `docs/decisions/` 、Phase進捗資料。構成だけでなく、この記録と更新の運用も引き継ぐ。

## 2. 記録先

| 保存先 | 内容 |
| --- | --- |
| `docs/requirements/` | 利用者から見た仕様。入力、出力、権限、対象トーク、例外、完了条件 |
| `docs/architecture/` | 全体構成、責務、所有者、依存方向、主要な処理経路、資源上限 |
| `docs/decisions/` | 重要な判断。理由、比較した案、利点・欠点、影響、再検討条件 |
| `docs/implementation/` | 実装済みの挙動。起動・停止、主要関数、呼出関係、状態遷移、制約 |
| `docs/engineering/` | 開発・文書・性能・最小検証の共通規約 |
| `docs/research/` | 調査・実験。版、条件、結果、未確認点、採否 |
| `docs/operations/` | 配備、状態確認、障害切分け、復旧、移行、切戻し |
| `docs/plans/` | 今後の作業、依存順、各Phaseの進捗と未完了事項 |
| 各機能の `docs/` | そのコードの仕様・関数・実験の詳細。全体資料から参照する |

必要な資料が生じた時点で作る。実装のない機能へ空の資料や雛形を大量に作らない。同じ説明を全体資料と機能資料へ複製せず、詳細の記録先を決めてリンクする。

## 3. 実装資料に残すこと

主要な公開関数・状態を持つ関数・境界処理について、次を記録する。

- 役割、入力、出力と失敗結果。
- 呼出元、呼び出す共通Serviceや後続処理。
- 所有する状態、永続化、期限と取消。
- 同時実行・件数・byte・時間の上限と、上限到達時の扱い。
- 再起動・再接続・結果不明でどう復旧するか。

必要なら関数の対応表と1本の処理フローでまとめる。型やコードを大量に貼り付けるのではなく、相互関係と設計意図を残す。単純な関数はモジュール内の役割説明にまとめ、記述量を抑える。

## 4. 作業と更新

1. 対象のrequirements、architecture、decisions、実コードと近傍docsを確認する。
2. 仕様変更がある場合は変更内容を明示する。利用者が確定した要件と提案を分ける。
3. 重要な設計変更は実装前に理由とトレードオフを示し、decisionsへ残す。
4. 最小限の実装・検証を行い、同じ作業で実装資料と関連リンクを更新する。
5. 計画の完了条件を照合し、実装済み・検証済み・未完了を区別して進捗を記録する。

仕様資料は期待する挙動、実装資料は現在の挙動を示す。食い違いが見つかった場合は「資料が古い」「実装が仕様未達」「仕様が未決定」のどれかを確認して修正する。

## 5. 設計判断・実験の最低限の記録

設計判断には状態（提案・採用・見送り・廃止）、日付、問題、決定、理由、トレードオフ、変更条件を残す。

実験には対象版・commit、実行環境、仮説、条件、実測結果、結論の範囲、未確認点を残す。再実行に必要な最小手順を添え、期待値を実測値として書かない。

調査済み、オフライン検証済み、実LINE確認済み、本番観測済みを区別する。PUSH接続・heartbeatの成功をメッセージ受信や全件処理の成功へ読み替えない。

## 6. 品質と保存形式

- 日本語を含むMarkdown等はBOM付きUTF-8で保存する。
- 文書更新時にリンク・参照関数・採用版・現行設定値を確認する。
- 旧実験は日付・対象版を付けて残し、現在の既定動作と区別する。
- 実装が変わった資料をそのまま現在仕様として案内しない。
- テストは最小限。文書整備を理由に巨大なTest Suiteや汎用Frameworkを追加しない。

2026-10-04、利用者向け文面は[Messages](../../crates/kbc-core/docs/MESSAGES.md)のキーを使う。権限案内・状態ラベルなどの共通キーを優先し、新規キーはschema・用途別txt・呼出を同時に追加する。定型helpは引き続きtxt追加だけで登録できる。
